Wi-Fi 热力图 · 数据采集操作手册

用 ESP32-C6 采集无线信号，重建整个房间的信号强度分布

房间尺寸 6.62 m × 7.74 m（51.2 m²，空房间）
路由器 1 台，固定在墙角
采集板 ESP32-C6 × 2
测点总数 25 个（20 训练 + 5 验证）
分区方式 4 列 × 5 行 = 20 块
单点耗时 约 60 秒

编制日期：2026-10-15　|　工具版本：ESPectre CLI (git 899a3fb)

1. 需要准备什么

物品数量说明
ESP32-C6 开发板2 块任意 C6 开发板均可（如 ESP32-C6-DevKitC）
USB 数据线2 条必须能传数据，不能是纯充电线。烧录和供电都要用
路由器1 台只要能开 2.4 GHz Wi-Fi 就行，越普通越好（信号太强反而不利于区分位置）
卷尺1 把5 m 以上，用来量区块边界

为什么用美纹纸：这个项目最大的误差来源不是设备，而是"每次板子摆的位置不一样"。在地上贴出格子、每次都摆到格子正中心，比换设备、换算法有用得多。

时间估算

双板并行，25 个测点约 20 分钟一轮。建议一共采集 3 轮（不同时间段，比如上午 / 下午 / 晚上），总计约 1 小时。多轮数据能明显提升模型稳定性。

3. 第一步：把路由器固定死

这一步只有一条规矩：路由器一旦放好，整个项目期间就不能再移动，也不能改设置。它一动，之前采的所有数据全部作废。

1
选位置：房间的一个墙角。

手册里假定路由器在左下角。我们把那个角定为坐标原点 (0, 0)，实际摆放时把它放在离两面墙各约 30 cm 的位置（避免紧贴墙面导致信号反射异常），即 (0.30, 0.30)。

坐标系约定（后面所有表格都用这个）：
· 原点 = 路由器那一侧的墙角
· x 轴 = 房间宽方向，总共 6.62 m
· y 轴 = 房间长方向，总共 7.74 m
· 板子插上电后，坐标 (x, y) 表示它离两面墙的距离（米）
2
调整路由器设置（只有这几项，做完就不要再动）
设置项设成原因
2.4 GHz 频段开启ESP32-C6 只在 2.4 GHz 上工作
信道固定在 1 / 6 / 11 之一自动信道会在采集过程中跳频，数据前后不可比
信道带宽20 MHz带宽越大越容易受邻居干扰
发射功率保持默认调低会让远处测点信号弱到测不出
3
找出房间里的干扰源，采集时关掉。

微波炉、无线耳机、蓝牙音箱、其他正在下载的设备，都会让数据抖动。采集期间请让房间保持安静、无人走动。

4. 第二步：划分区块、贴胶带

4.1 为什么要把房间分成格子

如果不分区，你可能会想"随便找几个地方测测就行"。问题是这样测出来的点分布不均匀，模型不知道该往哪个方向外推，画出来的热力图会有一块块的假色斑。

把房间切成大小一致的格子，每个格子中心测一次，就能保证：测点在空间上均匀铺开，模型在每个区域都有参考。

4.2 怎么分：4 列 × 5 行

方向房间长度分几份每一份是
x（宽 / 6.62 m）6.62 m4 份1.655 m
y（长 / 7.74 m）7.74 m5 份1.548 m

4 × 5 = 20 个格子。每个格子的尺寸约 1.66 m × 1.55 m——比一块板子大得多，所以摆板子的位置误差不会是主要问题。

4.3 三种点，作用不同

类型数量摆在哪作用
训练点
P11–P54		20 个 每个格子的正中心 模型靠这 20 个点的数据学习"哪个位置信号多强"
验证点
V01–V05		5 个 格子之间的交界处（四条线交叉的位置） 这 5 个点不参与训练。训练完之后拿它们来考试：模型没见过的位置，猜得准不准？
为什么验证点要放在线上而不是格子中心：如果验证点也放在格子中心，它跟最近的训练点只差不到 1 米，模型几乎等于"抄答案"，测不出真实水平。放在交界处，离最近的训练点约 1.1 米，才能真正考验模型。

4.4 现场怎么贴

  1. 在路由器那一侧的墙角贴一条标记，作为原点。
  2. 沿着 x 方向（宽）量出 1.655 m、3.31 m、4.965 m 三个位置，从墙根一直贴到对面墙，共 3 条竖线。
  3. 沿着 y 方向（长）量出 1.548 m、3.096 m、4.644 m、6.192 m 四个位置，贴 4 条横线。
  4. 这样地面就出现了 20 个格子。在 每个格子的正中心贴一个小方块胶带，写成 P11、P12……（这就是训练点）。
  5. 在 线交叉的位置贴一个小三角，写成 V01……（这就是验证点，只有 5 个，位置见下表）。

4.5 点位图

图 1　房间分区与测点位置。蓝点 = 20 个训练点，橙色三角 = 5 个验证点，红星 = 路由器。建议把这张图打印出来贴在墙上。

5. 第三步：给 ESP32-C6 烧录固件、连上 Wi-Fi

两块板子都要做一遍，步骤完全一样。

必须用 Chrome（或 Edge）。Safari 和 Firefox 不支持网页烧录功能，会看不到"连接 USB 设备"的按钮。
1
接上板子

用 USB 数据线把 ESP32-C6 插到 Mac 上。板子上通常有两颗按键，一颗标 BOOT 或 IO9，一颗标 RESET 或 EN。

2
打开烧录页面

在 Chrome 里打开：https://espectre.dev/tools/flash/

点击页面上的 Connect USB device，在弹出的列表里选择你的板子（一般显示为 USB JTAG/serial debug unit 或 CP2102 / CH340 之类）。

3
选择固件版本并烧录

页面检测到芯片后会让你选版本：选 Release（正式版）。然后确认开始烧录，烧录期间不要拔线、不要关网页，等到板子自动重启。

如果页面一直连不上板子：让板子进入下载模式——按住 BOOT 不放 → 按一下 RESET → 松开 BOOT → 再点一次 Connect USB device。
如果列表里一个设备都没有：多半是数据线的问题，换一根（很多线只能充电不能传数据）。
4
填 Wi-Fi 账号密码

烧录完成后页面会引导你填写 Wi-Fi 名称和密码（就是第 3 节里那台路由器）。填完提交，板子会重启并连上网络。

路由器必须开着 2.4 GHz。如果你的路由器是"双频合一"，请到路由器设置里把它拆开，确保有一个独立的 2.4 GHz 网络名——ESP32-C6 连不上纯 5 GHz 的信号。
5
记下板子的 IP 地址

Mac 和板子连到同一个 Wi-Fi 后，在项目目录下运行：

cd ~/Desktop/deepworks项目/Wi-Fi热力图
tools/espectre/.venv/bin/python tools/espectre/espectre devices

你会看到类似这样的输出：

Found 2 device(s):
  esp32c6-xxxx   192.168.1.51   native
  esp32c6-yyyy   192.168.1.52   native

把这两个 IP 记下来（比如 192.168.1.51 和 .52），后面采集要用。建议在路由器管理页面里给这两块板绑定固定 IP，否则重启后 IP 变了会连不上。

想让浏览器也能看到板子？打开 https://espectre.dev/tools/monitor/，填入板子 IP，可以看到实时的 CSI 数据流和信号状态。采集前用这个页面确认板子工作正常，很方便。

6. 第四步：采集数据（重点）

6.1 先搞清楚"采集"到底在干什么

板子通过 Wi-Fi 不断收到路由器发来的信号包，每个包里都带着这趟传播的信道状态信息（CSI）——可以理解成"这趟信号一路上的详细体检报告"。板子把这些报告打包保存，就得到了这个位置、这个时刻的信号特征。

我们要采集的核心数字是 RSSI（信号强度，单位 dBm），它是最直观的一条："这个位置信号有多强"。CSI 的细节数据也会一起存下来，作为备用。

6.2 一条完整的采集命令，逐项拆解

下面这条命令就是采一个测点的全部内容：

tools/espectre/.venv/bin/python tools/espectre/espectre collect \
  --target 192.168.1.51 \
  --label p11 \
  --duration 60 \
  --pps 100 \
  --ready-stable-seconds 5 \
  --detector lightweight \
  --description "point=P11;block=R1C1;role=train;x=0.83;y=0.77;round=r1"
参数我们用的值什么意思
--target192.168.1.51板子的 IP 地址。哪块板子采就填哪个
--labelp11测点编号，全小写。数据会存进以它命名的文件夹，必须和测点号一模一样
--duration60采集 60 秒。100 pps × 60 秒 ≈ 6000 个数据包，足够算稳定统计量
--pps100路由器每秒发 100 个包。数值太小样本不够，太大容易丢包
--ready-stable-seconds5关键参数。检测器要连续 5 秒认为"房间是静止的"才开始保存。这就是为什么人必须退出房间
--detectorlightweight用轻量检测器。我们只是在借它的采集能力，用什么都行
--descriptionpoint=P11;…给这批数据贴的标签，把测点号、坐标、轮次写进去，以后翻数据不会认错
三个绝对不能错的地方：
① --label 的内容必须是测点号的小写，写错了数据就归错位置了。
② 摆好板子后，人要退出房间，把门带上。站在房间里会让信号反射乱跳，数据直接废掉。
③ 采集期间不要碰板子、不要动路由器、不要开微波炉。

6.3 正式采集前，先试采一个点

先拿 P11 试一次，确认整条链路是通的：

cd ~/Desktop/deepworks项目/Wi-Fi热力图
bash scripts/02_collect_point.sh P11 192.168.1.51

脚本会问你确认测点位置，按回车后开始采集。60 秒后你应该看到它把数据归档到 data/points/p11/。

如果这一步成功了，说明设备、网络、采集程序全部就绪，可以开始批量采集。

6.4 一次跑完 25 个点

把两块板子的 IP 填进去，脚本会按"一批两个点"的节奏提示你摆板子——你只需要摆好、回车、等提示、再摆下一个：

cd ~/Desktop/deepworks项目/Wi-Fi热力图
bash scripts/03_collect_round.sh 192.168.1.51 192.168.1.52 r1

最后一个参数 r1 是这一轮的编号。跑第二轮就写 r2，第三轮写 r3。

输出会长这样，一批一批往前走：

------------------------------------------------------------
 第 1 批
   板A -> P11  (区块 R1C1, x=0.83 m, y=0.77 m)
   板B -> P12  (区块 R1C2, x=2.48 m, y=0.77 m)

   请把板子摆到胶带标出的对应格子中心，人退出房间，然后按回车。
   P11: 新增 1 个文件
   P12: 新增 1 个文件
------------------------------------------------------------
只有一块板子也能跑：命令里只填一个 IP 就行，脚本自动切成单板模式，时间翻倍（约 40 分钟一轮）。
中途想停：按 Ctrl + C。已经采好的数据都在硬盘上，不会丢。

6.5 建议采三轮

同一个位置在不同时段测出来的信号会略有不同（受环境温度、周围设备、以及人本身的影响）。同一个点采多轮，模型能学到"这里的平均水平是多少、抖动有多大"，比只采一轮准得多。

建议三轮分散在一天的不同时间，比如上午 10 点、下午 3 点、晚上 8 点。

7. 第五步：整理数据

采完之后，data/points/ 下面会散着一堆小文件（一个测点一个文件夹，每次采集产生 1 个 .npz）。这些文件机器能读、人看不懂，需要汇总成表。

跑这条命令

cd ~/Desktop/deepworks项目/Wi-Fi热力图
tools/espectre/.venv/bin/python scripts/04_build_dataset.py

它会给你两张表

文件内容
data/points_features.csv 明细表：一行 = 一个原始文件。用来查账、排查坏数据
outputs/测点汇总表.csv 汇总表：一行 = 一个测点。这张是后面建模真正要用的

汇总表里重要的列

列名含义
point_id测点编号，如 P11
roletrain = 训练点，validate = 验证点
x_m / y_m这个测点的坐标（米）
n_packets一共采到多少个包。6000 左右算正常
rssi_median信号强度中位数（dBm），这是最关键的一列
rssi_std信号抖动程度。这个值越小，说明采集环境越稳定
rssi_p10 / rssi_p9010% 和 90% 分位数，反映信号的波动范围
rssi_sourcedevice_rssi_dbm = 板子直接上报的；csi_power_proxy = 由 CSI 推算的替代值

怎么判断数据好不好

现象说明什么怎么办
n_packets 明显低于 6000丢包严重，可能是信号太弱或信道拥挤重采该点；换信道再试
rssi_std 特别大（>4）采集期间有干扰，或者有人在房间里走动确认无人、关掉干扰源，重采
某个点 rssi_median 明显偏离邻居板子摆错位置，或者数据里混进了别的测点核对 --label 和实际摆放位置
脚本提示"尚未采集的测点"还有测点没采按提示把缺的补上
合并多轮数据：如果同一个测点采了 3 轮（产生了 3 个 .npz），脚本会自动把它们合并成一个测点统计。不需要你手工挑文件。

8. 第六步：生成热力图

跑这条命令

cd ~/Desktop/deepworks项目/Wi-Fi热力图
tools/espectre/.venv/bin/python scripts/05_train_and_plot.py

它会同时跑三个模型，互相比较

模型原理特点
IDW
反距离加权		 没测过的位置，就看它周围的测点，谁近信谁（按距离倒数的平方加权） 不需要训练，一秒出结果。但只会"和稀泥"，细节差
路径损耗拟合
物理公式		 假设信号只随"离路由器的距离"衰减，拟合一个公式 P = P₀ + n·10log₁₀(d) 只用距离，非常简单。信号规律干净时它最强，真实房间里往往偏乐观
GPR
高斯过程回归		 小样本机器学习。不预设衰减规律，让数据自己说话，还能给出不确定度 本项目的重点方法。20 个点这种小样本下，它是表现最稳的机器学习模型

输出三个文件

文件内容
outputs/热力图_预测.png最终成品：整个房间的 RSS 分布彩色图
outputs/热力图_对比.png三个模型并排对比，一眼看出谁准
outputs/模型评估报告.md误差数字表 + 结论

怎么看结果好不好

脚本会打印两张误差表。重点是"外部验证"那一张——它表示"用 20 个测点建模，去猜 5 个从没测过的位置"：

指标含义参考标准
MAE平均绝对误差，单位 dB。越小越好< 3 dB 算不错；< 1.5 dB 很好
RMSE均方根误差，对大误差更敏感和 MAE 接近说明没有离谱的异常点
R²拟合优度，越接近 1 越好> 0.8 说明模型抓住了主要规律

成品长这样（示例）

图 2　热力图示例（用模拟数据生成，仅示意效果）。红色 = 信号强，蓝色 = 信号弱；黑点是训练点，红三角是验证点，红星是路由器。可以看出离路由器越远颜色越冷。

图 3　三种方法并排对比。配色越接近，说明模型越吻合。

上面两张图是用模拟数据生成的示例，不是你的真实测量结果。你跑完真实采集后，同名的正式文件会覆盖生成在 outputs/ 下（示例文件带 示例_ 前缀，可以对照着看）。
关于"机器学习到底有没有用"：如果你采的是空房间、只有一台路由器，路径损耗这种物理公式可能就已经很准了——这不代表模型没用，而是说明这个场景太干净。
想让机器学习真正发挥价值，可以试试：放两三个路由器（多个信号源会让空间特征复杂得多），或者在房间里加一些家具（制造多径反射）。这时 GPR 的优势就会明显体现出来。

9. 常见问题排查

现象可能原因 & 解决办法
espectre devices 一个设备都找不到 ① 板子没通电 / 没连上 Wi-Fi → 用 espectre monitor 接串口看日志
② Mac 和板子不在同一个网段 → 检查本机 IP（01 脚本会打印）
③ 路由器开了"AP 隔离"或"访客网络隔离" → 到路由器设置里关掉
Chrome 里点 Connect USB device 没反应 / 列表为空 ① 数据线只能充电 → 换一根
② 板子没进下载模式 → 按住 BOOT → 按 RESET → 松开 BOOT
③ 用的是 Safari → 换 Chrome
采集时报 too few packets / 包数很少 ① 板子离路由器太远，信号弱 → 正常现象，检查该点距离
② 信道被邻居占用 → 换 1/6/11 里的另一个信道
③ 路由器在省电模式 → 关闭 Wi-Fi 节能选项
采集一直卡在 "waiting for stable" 房间里有东西在动（风扇、宠物、窗帘飘动），或者有人还在房间里。
把 --ready-stable-seconds 改成 0 可以关掉这个等待（但数据质量会下降）。
找不到采集出来的数据文件 原始文件在 tools/espectre/data/<label>/，脚本会把它复制到 data/points/<label>/。两边都看看。
跑 Python 脚本报 ModuleNotFoundError: numpy 用了系统的 python3。必须写 tools/espectre/.venv/bin/python
生成的热力图有明显的色块边界 测点太少或分布不均。补采缺失的测点，或多采几轮。
